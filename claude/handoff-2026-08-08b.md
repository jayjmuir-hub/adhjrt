## ⚠️ The one thing to internalise

**Four separate times, a check reported success while measuring the wrong
thing** — and that is on top of the four the morning handoff already lists. A
harness that had never rendered the page. `overflow-x:hidden` that hid an
overflow instead of fixing it, while the audit read `sidewaysPx: 0`. A CSS
selector written against the source spelling of an inline style, which the
renderer re-emits with spaces, so it matched nothing in a browser. And a test
that passed against the exact bug it was written to catch.

**The pattern is always the same: the instrument agreed with the intention.**
The ones that caught it were counting something *different* — overflowing AND
unreachable, not just scrollWidth; `document.fonts.ready` status, not the
screenshot; `el.matches()` in a live page, not the diff.

⚠️ **And a self-inflicted one worth knowing:** a tombstone comment that quotes
the code it replaced becomes a **decoy** for the next regex. One did, and
reported a whole working fix as missing. Anchor searches on something only the
live rule has.

## Bridge note

This session pushed from the sandbox via `git bundle` →
`device_commit_files` → the PC, six times, and it works. ⚠️ `CLAUDE.md` § 1b
was **wrong** about the fetch command and is now corrected: it is
`git fetch <bundle> dev` — the source ref alone. A bare fetch asks for `HEAD`,
which a `origin/dev..dev` bundle does not carry.

⚠️ **The stop hook will fire falsely after every one of those transfers.** The
commit leaves the sandbox as a bundle and is pushed from the PC, so the
sandbox's `origin/dev` ref never learns the remote moved. `git fetch origin` in
the sandbox after each PC push clears it. **Do not push to silence it.**
